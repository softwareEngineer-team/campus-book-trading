# 校园二手教材交易管理系统
Campus Second-hand Textbook Exchange System

## 1. 项目简介

本项目面向在校学生和平台管理员，开发一个支持二手教材发布、查询、预约交易及订单管理的Web系统。

学生可以作为卖家发布和管理闲置教材，也可以作为买家搜索、收藏和预约教材，并通过线下方式完成交易。平台管理员负责用户管理、商品审核及交易纠纷处理。

项目旨在提高校园闲置教材的流通效率，降低学生购买教材的成本。

## 2. 项目背景与目标

目前，校园二手教材交易主要依赖微信群、QQ群、校圈及其他非专门化渠道，可能存在教材信息分散、版本难以匹配、交易状态不明确等问题。

本项目拟建立面向校园的二手教材交易平台，实现：

- 集中发布和查询二手教材信息。
- 根据教材名称、课程名称、ISBN等条件搜索教材。
- 支持买卖双方进行预约与订单状态管理。
- 支持交易评价、举报处理与平台管理。
- 提供清晰的交易记录和状态追踪。

以上问题和需求属于初步分析，后续将通过真实用户调研进一步确认。

## 3. 用户角色

| 角色 | 主要权限 |
|---|---|
| 买家 | 搜索教材、收藏商品、预约购买、管理购买订单、评价交易 |
| 卖家 | 发布教材、编辑或下架商品、处理预约、管理出售订单 |
| 平台管理员 | 管理用户、审核商品、处理举报和交易纠纷 |

注：买家和卖家是学生在不同交易场景下承担的业务角色，同一学生账号可以同时具有两种身份。是否满足课程对三类用户角色及权限的要求，需在立项时与教师确认。

## 4. 初步功能范围

### 4.1 用户与权限管理
- 用户注册与登录
- 个人信息管理
- 角色权限控制

### 4.2 教材与商品管理
- 教材信息查询
- 二手教材发布、修改、下架
- 教材版本、ISBN、价格和成色管理

### 4.3 教材搜索与收藏
- 关键词搜索
- 按课程、教材名称等条件筛选
- 商品详情展示
- 收藏管理

### 4.4 预约与交易管理
- 商品预约
- 卖家确认或拒绝预约
- 订单取消与交易完成
- 交易状态跟踪

### 4.5 平台管理
- 商品审核与违规处理
- 用户管理
- 交易评价与举报处理
- 消息通知

## 5. 开发范围与约束

- 主要面向校园内的二手教材交易。
- 交易采用线下交付方式。
- 初期不实现在线支付、物流配送。
- 计划集成第三方消息或邮件通知服务。
- 重点考虑商品重复预约、订单状态一致性及权限控制等技术风险。

## 6. 开发过程

项目计划采用增量开发模式，将功能划分为三个可交付增量：

| 增量 | 主要内容 |
|---|---|
| Increment 1 | 用户管理、教材信息、商品发布与搜索 |
| Increment 2 | 商品预约、订单管理与交易状态维护 |
| Increment 3 | 评价举报、平台管理、通知及系统完善 |

选择增量开发的原因：

1. 系统功能可以按业务流程逐步实现。
2. 每个增量能够形成可测试的功能成果。
3. 用户调研与测试反馈可以用于调整后续需求。
4. 有利于团队分阶段开展开发、评审和质量检查。

具体范围和技术方案将在需求调研后进一步确定。

## 8. GitHub协作规范

- 所有开发与文档修改通过GitHub进行版本管理。
- `main` 为受保护的主分支，修改通过Pull Request合并。
- 每个PR至少由一名其他成员评审。
- 使用Issue管理需求、开发任务、缺陷及需求变更。
- 使用Milestone跟踪项目阶段和增量。
- 通过GitHub Actions逐步建立自动化测试流程。
- 两轮迭代之间至少调整一次结对或代码评审对象。
- AI辅助生成的重要成果需要人工检查与验证，并记录使用情况。
